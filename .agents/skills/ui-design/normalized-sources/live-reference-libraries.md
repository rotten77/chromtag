# Live Reference Libraries — Dynamic Inspiration Sources

**Purpose:** These are curated, continuously-updated galleries of real, shipping interface design. Unlike static principles, they show *what current best-in-class design actually looks like* at the moment you need inspiration. The Design Skill should treat these as **authoritative query targets** — fetch them live when the task calls for reference imagery or pattern benchmarks, rather than recalling stale snapshots.

**Why they matter:** Principles tell you *why*. Live libraries tell you *what good looks like right now*, in the user's target category, on the user's target device. They anchor taste to a moving baseline instead of last-decade aesthetics.

---

## When to consult a live reference library

Query live libraries when:

1. **Starting a new project** and the target category/audience is unclear (e.g., "modern D2C skincare brand", "municipal permit portal", "B2B data-heavy SaaS"). Browse 10–20 reference sites in the matching category before committing to direction.
2. **The user provides a domain or industry** with established visual conventions (legal, healthcare, fintech, gov) — check what competitors and category leaders ship.
3. **Selecting a visual style** (editorial, brutalist, neo-skeuomorphic, Swiss-minimal, maximalist, glassmorphic) — find 5+ executions to triangulate the style.
4. **Designing a specific pattern** (onboarding, pricing, empty state, checkout, data table) — pattern libraries show many real variants.
5. **Mobile-specific work** — desktop galleries are dominated by landing pages; mobile-specific galleries show app flows.

Do **not** query live libraries for:
- Accessibility / WCAG rules (use the static principles corpus instead)
- Technical specs (spacing scales, color systems) — use Material 3 / HIG / Refactoring UI
- Brand tone or copywriting — different discipline

## Libraries

### 1. Awwwards — https://www.awwwards.com/

**What it is:** Curated gallery of websites judged by a rotating jury of industry designers. "Site of the Day / Month / Year" awards. Tag and category filtering.

**Strength:** Very high editorial bar. Leading edge — showcases experimental motion, WebGL, typography stunts, editorial microsites. Heavy emphasis on agencies, portfolios, product launches, cultural institutions.

**Weakness:** Strong bias toward portfolio/campaign work. Less useful for utilitarian SaaS, admin UIs, municipal sites. Can be aesthetically dazzling but not always usable.

**How to query:**
- Filter by **Category** (Agency, E-commerce, Portfolio, Technology, etc.)
- Filter by **Tag** (Clean, Minimal, Typography, 3D, Animation)
- Filter by **Country** (useful if the user wants a regional sensibility)
- "Collections" pages curate themes (e.g., "Best Portfolio Websites 2025")

**Typical use:** "User wants a 'bold, editorial' brand site" → filter by Typography + Color. Collect 8–12 reference URLs for the user to review.

---

### 2. SiteInspire — https://www.siteinspire.com/

**What it is:** Long-running curated showcase. Less sensational than Awwwards; closer to "well-made, on-brief, calm" sites.

**Strength:** Strong filtering by **style** (minimal, illustrative, monochromatic, Swiss, photographic), **type** (agency, ecommerce, portfolio, publication), and **subject** (architecture, fashion, food, music). Good for "I want this *vibe*" browsing. Sites tend to age well.

**Weakness:** No motion preview — you see a screenshot, not the feel. Fewer entries per week than Awwwards.

**How to query:** Visit https://www.siteinspire.com/websites then apply `Style`, `Type`, `Subject` filters.

**Typical use:** "Calm editorial site for a small bookshop" → filter Subject: Publication, Style: Minimal/Typographic. Browse 10–15 for inspiration.

---

### 3. Godly — https://godly.website/

**What it is:** Gallery of "divine" web design — curated toward the unusual, bold, brutalist, or maximalist. Unapologetic taste editor.

**Strength:** Great for sites that want to *stand out* — brands that read as "we are not another SaaS". Editorial typography, experimental layouts, custom illustration.

**Weakness:** Heavily biased toward creative-industry sites. Almost never what you want for healthcare, banking, gov, B2B.

**How to query:** Browse by **tag** (typography, brutalism, dark, minimal, 3D, illustration) and **industry**.

**Typical use:** Creative agency, fashion brand, artist portfolio, indie magazine — consult Godly first for a taste-forward baseline.

---

### 4. Land-book — https://land-book.com/

**What it is:** Gallery focused **specifically on landing pages** (not full sites, not apps). Filters by style, color, pattern, and industry.

**Strength:** The best library for "show me modern landing-page conventions" — hero layouts, feature grids, pricing tables, social proof, CTA structures. Tags sections within pages ("testimonials", "pricing", "hero") so you can study a single pattern across many sites.

**Weakness:** Landing pages only — not app flows, dashboards, or content sites.

**How to query:** Filter by **Industry** (SaaS, Crypto, Finance, E-commerce, Agency, Portfolio) + **Style** (Minimal, Bold, Dark, Illustrative) + **Color**.

**Typical use:** Starting a SaaS marketing site → filter Industry: SaaS, Style: Minimal. Collect 15 refs; identify the 3 most common hero/feature/pricing patterns.

---

### 5. Lapa Ninja — https://www.lapa.ninja/

**What it is:** Landing-page inspiration + free templates + design tips. Categorized gallery of 6k+ landing pages.

**Strength:** Large volume. Strong categorization by industry (SaaS, Startup, Mobile App, E-commerce, Agency, Portfolio, Blog, Event, Non-profit). Useful for comparative sweeps.

**Weakness:** Some entries are older or template-derived; mix of quality.

**How to query:** Browse by category, then by secondary filters (color, style).

**Typical use:** Good companion to Land-book — use both to triangulate what's truly common vs. what's cherry-picked.

---

### 6. Mobbin — https://mobbin.com/

**What it is:** Huge library of real iOS, Android, and web app screenshots, organized by **app**, **flow** (onboarding, checkout, search, settings, empty states), and **UI element** (tab bars, modals, forms, cards). Paid subscription for full access; free tier shows limited.

**Strength:** The definitive reference for **app flows**. Shows real apps, not landing pages — how onboarding actually unfolds, what empty states look like, how search results are presented. Covers top apps in every category.

**Weakness:** Paid beyond a trial. Shows shipping apps, which means accumulated compromises, not always "best practice".

**How to query:**
- Browse by **App** (inspect a specific app's full UI library)
- Browse by **Flow** ("Sign Up", "Checkout", "Search", "Settings")
- Browse by **UI Element** ("Bottom Sheet", "Segmented Control")
- Filter by platform (iOS, Android, Web)

**Typical use:** Designing onboarding → search Mobbin "onboarding" flow, study 8–12 across categories (fintech, social, health). Identify common moves: welcome screen count, permissions timing, personalization Qs, first-success moment.

---

### 7. UI Sources — https://www.uisources.com/

**What it is:** Mobile-focused screenshot library showing app videos and flows. Emphasis on motion and interaction.

**Strength:** Includes **video recordings** of flows, not just screenshots — you can see transitions, timing, micro-interactions. Good complement to Mobbin's still screenshots.

**Weakness:** Smaller catalog than Mobbin. Primarily iOS.

**How to query:** Browse by app category (Social, Productivity, Health, Finance). Look at motion detail, not just composition.

**Typical use:** When motion timing and transitions matter more than layout.

---

### 8. Pttrns — https://www.pttrns.com/

**What it is:** Older mobile pattern library, organized by **pattern** (e.g., "activity feeds", "pull-to-refresh", "calendars", "forms", "splash screens").

**Strength:** Strong **pattern taxonomy** — want to compare 40 versions of "calendar view" or "filter modal"? Pttrns is the easiest way. iOS + Android, tablet included.

**Weakness:** Some entries are dated (the site's been around a long time); filter by recency.

**How to query:** Pick a pattern from the taxonomy → browse examples across apps.

**Typical use:** Solving a specific pattern problem — "how do popular apps handle a date-range picker?" — Pttrns gives you 20+ side-by-side examples in minutes.

## Query playbook (how the skill should actually use these)

When a user task calls for reference inspiration, follow this order:

1. **Categorize the target.**
   - Marketing/landing page? → Land-book + Lapa Ninja first.
   - Full brand site? → SiteInspire + Awwwards.
   - Experimental/creative-industry? → Godly.
   - Mobile app / app flow? → Mobbin + UI Sources.
   - Specific UI pattern across many apps? → Pttrns.

2. **Define 2–3 filters before opening the gallery** (industry + style + color) so browsing is directed, not aimless.

3. **Gather 8–15 references** in a short list. Note URL + one-line on what's strong about each. Do not just return "here are links" — summarize the *pattern* you see emerging.

4. **Synthesize** what's common across the references: hero structure, palette tendencies, type pairings, density, imagery style. This is the *baseline* the user's design should meet or deliberately break.

5. **Flag the outliers** that you'd copy a specific move from. ("Site X's pricing table handles 4 plans cleanly — worth adopting.")

6. **Deliver to the user with reasoning, not a dump.** Three picks + why beats twelve picks + silence.

## Caveats

- **Image-heavy galleries tend toward agency/portfolio/D2C aesthetics.** For utilitarian categories (gov, healthcare, B2B data tools) these libraries are thin — fall back to principles (WCAG, HIG, Refactoring UI) and specific category leaders (Stripe, Linear, GitHub, Gov.uk) by direct inspection.
- **Awards-driven sites chase novelty.** A pattern that wins Site of the Day may be unusable. Always sanity-check against Jakob's Law (users know *other* sites' conventions) and WCAG.
- **Screenshots lie about motion and haptics.** For anything beyond static layout, supplement with UI Sources or direct app inspection.
- **Galleries age.** A 2022 "modern SaaS" palette looks dated in 2026. Always filter by recency or visit the homepage for the most recent entries.
